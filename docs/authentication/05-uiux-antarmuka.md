## Perubahan yang diselesaikan

- Form resmi login/register/recovery/reset/verify memakai hook request nyata, terpisah dari `AuthForm`/`AccountPreview` sintetis. Login tetap memakai kartu maksimum400px existing, identifier username, show-password, Google putih dengan G multicolor, dan tautan pemulihan.
- Signup sukses201 sekarang menampilkan akun dibuat/kontak belum verified, menawarkan kirim verifikasi email bila tersedia, atau verifikasi nomor melalui pengaturan akun. Pengiriman email memerlukan klik tersendiri. Kanal absent menjelaskan keterbatasan tetapi akses workspace/password login tetap tersedia; tidak mengklaim kode/email sudah terkirim.
- Login202 menampilkan panel OTP tanpa redirect workspace. `readLoginResult` membedakan challenge dan sesi penuh, menolak respons tidak lengkap/redirect asing, dan memprioritaskan challenge walaupun response juga memuat redirect. Verifikasi/resend menggunakan token challenge transient; resend mengganti token/kode lama di UI.
- `SecurityDto` memuat `smsOtpEnabled`; panel `SmsOtpSettings` PATCH hanya flag tersebut. Enable membutuhkan fresh reauth, password, nomor verified dan konfigurasi SMS siap. Disable flag existing tetap memerlukan reauth. Backend tetap otoritas terakhir untuk flag dan sesi; UI tidak mengubah flag secara optimistis.
- Pesan akun membedakan kegagalan `role=alert` dan keberhasilan `role=status`; hook request menyediakan kedua status. Profil menolak nama hanya spasi sebelum request. Countdown429 menonaktifkan tombol/fieldset dan guard ref menolak submit duplikat sebelum rerender.
- Daftar sesi dimuat ulang ketika perubahan keamanan berhasil; kontak ditarik ulang saat security DTO berganti. Timestamp sesi nullable menampilkan tanda kosong. Customer/admin shell menampilkan nomor nyata jika email/nama tidak tersedia, tanpa email sintetis.
- Validasi telepon UI menerima08/628/+E.164; spasi/tanda kurung/hyphen dibersihkan sebelum POST. Nomor lokal selain08 dan nomor internasional tanpa+ ditolak inline. Server tetap memeriksa format, normalisasi dan uniqueness.
- Metadata auth/account noindex/no-referrer. CSS akun menahan kolom grid dan membungkus kontak panjang; padding kartu diperkecil pada390px, kontrol checkbox punya target44px. Tidak ada perubahan hook preview atau akses provider/DB dari preview.

## Alur pengguna dan state

| Alur                   | Langkah dan hasil                                                                                                                                                                                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Password login         | Identifier → password → CSRF → POST login → redirect lokal dari server, atau OTP202 → kode → POST verify → redirect setelah sesi diterbitkan                                                                           |
| Google                 | Capability boolean siap → tombol → CSRF → POST start → URL HTTPS endpoint otorisasi accounts.google.com saja. Missing capability/config membuat tombol disabled dengan penjelasan                                      |
| Signup                 | Nama/identifier/password12–256 karakter/kebijakan wajib → POST strict → status akun dibuat tetapi kontak belum verified → tawaran verifikasi atau lanjut workspace                                                     |
| Recovery email         | Identifier tervalidasi/provider siap → POST → pesan generik untuk akun eligible maupun unknown; tidak menerima proof email melalui JSON                                                                                |
| Recovery SMS           | POST forgot → challenge transient → OTP/resend cooldown → reset proof dari verify → password baru+konfirmasi → status berhasil dan tautan login                                                                        |
| Reset/verifikasi email | Baca fragment setelah mount → hapus fragment dan parameter token legacy dengan replaceState → tunggu tindakan eksplisit POST. Render/GET tidak consume proof; invalid/expired mengarahkan meminta link baru/pengaturan |
| Akun                   | Server guard sesi ACTIVE → GET DTO akun sendiri → PATCH nama saja; perubahan kontak tetap pending sampai proof berhasil                                                                                                |
| Security               | Reauth password atau Google untuk akun Google-only → freshness dari DTO server maksimum5 menit → password/link/unlink/contact/OTP/sesi. Metode terakhir disabled di UI; server wajib menolak bypass/race               |
| Perangkat              | GET metadata aman → delete sesi current membawa ke login; sesi lain/revoke others memerlukan reauth → refresh DTO                                                                                                      |

State idle/pending/error/success memakai hook bersama.400 memandu periksa isian/proof;401 menjelaskan sesi/kredensial tidak sesuai;403 REAUTH_REQUIRED meminta konfirmasi;409 menyarankan periksa metode;429 memakai Retry-After/counter;503 menjelaskan layanan belum tersedia; jaringan gagal memberi pesan aman. Payload provider/stack/error mentah tidak ditampilkan. Pending lock synchronous mencegah duplikat pada form sama; setelah selesai lock dilepas. OTP mempunyai expiry dan cooldown resend, serta disabled ketika reauth akun kedaluwarsa.

Token reset/OTP/verification hanya hidup dalam state/closure React dan tidak masuk input hidden, query redirect, localStorage/sessionStorage atau log UI. Navigasi/reload melepas state transient. Sukses reset ditampilkan dengan tautan masuk dan backend diwajibkan single-use/revoke sesi. Reauth Google melakukan navigasi penuh: proof email yang sebelumnya sudah dibaca ke memori tidak dipersistenkan untuk melewati navigasi; pengguna perlu membuka ulang tautan verifikasi setelah kembali.

## Kontrak frontend untuk backend06

DTO publik berada di `src/features/auth/types/auth-contracts.ts` dan `src/features/account/types/account-contracts.ts`; backend boleh mengimpor **type** ini. Tidak ada Prisma/provider/rahasia dalam DTO. Semua mutasi frontend melewati `authRequest`: bootstrap GET csrf setiap mutasi, header `X-CSRF-Token`, JSON, credentials same-origin, cache no-store, redirect error. Path dibatasi `/api/auth/*` dan `/api/account/*`, tanpa traversal/URL absolut. Pemeriksaan exact Origin/CSRF/ownership/RBAC tetap wajib di backend.

| Kontrak                                                   | Payload frontend                                               | Respons yang dikonsumsi                                                                                                                        |
| --------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| GET auth capabilities/csrf                                | —                                                              | `{ok:true,data:{google,emailRecovery,smsOtp}}` / `{ok:true,data:{csrfToken}}`                                                                  |
| POST auth login                                           | `{identifier,password,next?}`                                  | `{ok:true,redirectTo}` atau `{ok:true,data:{otpRequired:true,token,expiresIn,resendAfter}}`                                                    |
| POST auth register                                        | `{name,identifier,password}`; tanpa role/confirmation/checkbox | 201 `{ok:true,redirectTo,data:{verificationRequired,channel:'email'                                                                            | 'sms',verificationAvailable}}`                                |
| POST auth google/start                                    | `{intent:'login'                                               | 'link'                                                                                                                                         | 'reauthenticate',next?}`                                      | `{ok:true,redirectTo:<GoogleURL server>}`; callback redirect error hanya kode allowlist |
| POST auth forgot-password                                 | `{identifier}`                                                 | 202 generik; phone dapat menyertakan `data:{token,expiresIn,resendAfter}`                                                                      |
| POST auth otp/verify, otp/resend                          | `{token,code}` / `{token}`                                     | verify login `redirectTo`, recovery `data:{resetToken}`; resend `data:{token,expiresIn,resendAfter}`                                           |
| POST auth reset-password, email/verify                    | `{token,password}` / `{token}`                                 | `{ok:true,...}`; sukses reset tidak auto-login                                                                                                 |
| POST auth email/request                                   | `{identifier,purpose:'register'}`                              | 202 generik; tidak mengembalikan raw proof email                                                                                               |
| GET/PATCH account profile                                 | — / `{name}`                                                   | `data:ProfileDto`, termasuk email/phone/name/avatar nullable dan role empat nilai; flag verifikasi boolean                                     |
| GET/PATCH account security                                | — / `{smsOtpEnabled:boolean}`                                  | `data:SecurityDto`, termasuk hasPassword/googleLinked/emailVerified/phoneVerified/smsOtpEnabled/reauthenticatedUntil nullable ISO/capabilities |
| POST account reauthenticate, password                     | `{password}` / `{password,currentPassword?}`                   | `{ok:true,...}`; frontend refresh security setelah sukses, bootstrap ulang CSRF sebelum operasi berikutnya                                     |
| POST account google/unlink                                | `{}`                                                           | `{ok:true}`; UI membutuhkan password+minimal satu kontak verified cadangan                                                                     |
| POST account email/request, email/verify                  | `{email}` / `{token}`                                          | 202 receipt diterima /200 profil; email lama aktif sampai proof berhasil                                                                       |
| POST account phone/otp, phone/verify                      | `{phone}` / `{token,code}`                                     | 202 `data:{token,expiresIn,resendAfter}` /200 profil; resend account melalui phone/otp dengan nomor pending yang sama                          |
| POST account email/unlink, phone/unlink                   | `{}`                                                           | `{ok:true}`; tidak membawa target userId                                                                                                       |
| GET account sessions                                      | —                                                              | `data:{sessions:[{id,current,createdAt,lastSeenAt:string                                                                                       | null,expiresAt,deviceLabel}]}`; tanpa hash/token/IP/UA mentah |
| DELETE account sessions/{id}, POST sessions/revoke-others | body kosong / `{}`                                             | `{ok:true,...}`; ID sesi dari DTO, encodeURIComponent, server wajib scope owner                                                                |
| POST auth logout                                          | `{}`                                                           | 200 sukses → login/refresh; kegagalan tetap di UI, tanpa klaim cookie pasti sudah dihapus                                                      |

Backend06 wajib mempertahankan challenge fields di bawah `data`, reset proof setelah OTP valid saja, kode `REAUTH_REQUIRED` untuk fresh proof, timestamp ISO/null, serta token/sesi opaque hanya cookie HttpOnly. `smsOtpEnabled` harus mencerminkan status persisten aktual; DTO sementara false/enable503 bukan implementasi faktor login selesai. Respons login202 tidak boleh memberi akses private atau redirect sebelum verify. Panel OTP dan toggle frontend tersedia, tetapi enforcement/storage flag merupakan tugas backend06/core integrasi.

## Modul dan batas izin

Routing account/vendor adalah Server Component dengan `requireAccountSession`/`requireVendorSession`; page account juga mengulang guard, sehingga layout yang dipertahankan saat navigasi tidak menjadi satu-satunya pemeriksaan. Layout akun memilih home berdasarkan role tanpa membuka menu domain customer/admin kepada role lain. Profil/API memakai akun sesi sendiri tanpa userId dari browser. Guard customer/admin dan alias rute lama tetap milik backend/core/source existing.

Presentasi dipisahkan ke komponen kecil: password field, Google button, OTP form, registration success, profile, reauth, password, Google, kontak, SMS dan session list. Hook `useAuthRequest` menangani pending/lock/countdown/feedback; `useAccountResource` menangani pembacaan DTO/generation; `useTokenFragment` menangani proof sementara. Lib `auth-client`, `identifier-input`, `login-result` menangani kontrak browser. Komponen tetap di bawah200 baris pada checkpoint ini.

Tidak ada perubahan bisnis vendor, backend akun, payment atau provider. Preview memakai komponen/hook simulasi existing, label data contoh/noindex dan tidak mengimpor helper API nyata; unit SSR menegaskan route API tidak muncul pada form preview. Pembuktian nol request browser tetap bagian QA.
