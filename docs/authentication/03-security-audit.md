## Database dan batas kepercayaan runtime

Schema/migration mempertahankan CUSTOMER serta menambah CLIENT/VENDOR, nullable email, phone unique/verified, provider-subject unique, tokenHash unique dan smsOtpEnabled. CHECK mencegah enabled tanpa nomor verified; validasi proof/credential tetap di layanan. SQL parameter Prisma/tagged query memisahkan nilai dari perintah; advisory lock identifier tidak menggantikan constraint unique.

`auth-runtime-grants.sql` mencabut UPDATE role/status/id dan kolom identity/session/proof immutable; trigger INSERT hanya CLIENT/ACTIVE untuk nama runtime `menujuakad_runtime_preproduction`. Owner/admin provisioning terpisah. Skrip menolak role superuser/bypassRLS/DDL/inheritance/ownership. Test data02 melaporkan grants lulus di PGlite; reviewer membaca sumber test/grants, tidak menerapkannya ke Neon.

Batas penting: immutable di sini membatasi UPDATE, sementara DELETE/INSERT diperlukan rotasi/accepted proof. Runtime tetap merupakan principal server tepercaya yang dapat menulis credential/session semua user; grants ini bukan isolasi per-user/RLS dan tidak menahan pemalsuan sesi setelah database/runtime sepenuhnya dikompromikan. Kepemilikan/role berasal dari session resolver dan transaksi layanan, bukan privilege kolom sebagai satu-satunya pertahanan.
