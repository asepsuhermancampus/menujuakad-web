# Inventaris dan Handoff Visual Stitch Menuju Akad

Tanggal: 7 Oktober 2026. Lingkup worker: inventaris sumber, inspeksi visual representatif, pemetaan rute, dan handoff komponen. Instruksi sesi terbaru mengizinkan slicing desain yang selesai dan deployment menujuakad.com; dokumen ini sendiri tidak mengubah kode produk, layanan, atau deployment. Panduan role `uiux.md`, AGENTS aplikasi, master spec, brief web 11, snapshot design system, progres dan changelog dibaca. Perubahan status bersama dikelola PM.

## Hasil dan sumber yang dapat dipakai

Proyek MCP yang dibaca langsung: **MENUJU-AKAD-UIUX**, `projects/12559574101879777472`. `get_project` dan `list_screens` berhasil. Daftar memuat 45 desain dan satu lampiran TXT. Seluruh 19 ID historis yang diberikan berhasil dibaca dengan `get_screen`: PUB-01–09, AUT-01–06, CUS-01–04. Total metadata: **64 desain, 53 kode layar unik**, bukan 64 fitur selesai.

**62 screenshot resolusi penuh valid, nol HTML desain valid.** URL HTML mengalihkan ke halaman `Sign in - Google Accounts` di `accounts.google.com`, walaupun respons HTTP 200. Isi bukan markup Menuju Akad. Percobaan URL asli, parameter `download=1`, dan `export=download` pada sampel PUB-01 tetap mengalihkan ke login. Respons HTML salah dihapus; `html_path=null`, `htmlValid=false` untuk seluruh desain. Tidak ada cookie/token autentikasi lokal yang dibaca. Developer memakai screenshot valid dan token sebagai fallback; jangan mengimpor wrapper/login Google atau mengklaim slicing dari HTML telah dilakukan.

Screenshot CUS-01 desktop (`3f8be25ae0eb4ba9b5190d593d7a967a`) dan CUS-02 desktop (`353a7f3c9fb94e26bfe66324ba2ea60f`) juga mengembalikan login, termasuk saat URL diberi `=s0`. Metadata ada, visual desktop tersebut belum terverifikasi. CUS-01 mobile/tablet tersedia sebagai referensi nyata; keduanya bukan bukti visual desktop identik.

## Keputusan pemetaan rute yang memerlukan perhatian

- Brief INV memakai `/u/[token]`; master memakai `/invitation/[slug]` dan resolver `/{slug}`. Manifest menempatkan rute kanonis master. Tautan personal bertoken adalah kebutuhan berbeda dari slug; `/u/...` yang terlihat pada tabel GST merupakan contoh visual, bukan kontrak token yang sudah aman. Resolver slug tidak boleh menelan prefix reserved. Token invalid tidak menampilkan identitas tamu.
- Brief ACC-01 memakai `/dashboard/account`; master memakai `/dashboard/profile` dan `/dashboard/settings`. Manifest memetakan profil ke `/dashboard/profile`; panel keamanan dapat dipecah ke settings oleh developer sesuai kontrak domain, tanpa membuat halaman identik di dua URL.
- Brief checkout tidak menyertakan orderId. Manifest memakai `/dashboard/billing/checkout/[orderId]`, mengikuti master. Status attempt/payment memiliki identitas sendiri; jangan menyatukan order dan payment menjadi angka statis di UI.
- PUB-06 `/how-it-works`, PUB-09 `/about`, PUB-10 `/terms`, PUB-11 `/privacy` merupakan perluasan visual/brief. Tautkan rute secara konsisten dan masukkan prefix pada daftar reserved bila resolver undangan diaktifkan.
- ERR-500 bernama “Pemeliharaan Sistem & Status Server”. Error tak terduga dan maintenance terjadwal memiliki status HTTP/perilaku berbeda; keduanya tidak boleh mengklaim jam selesai, data aman, atau progres 88% tanpa sumber operasional.
- EDT-08 dipetakan `?section=publish-check`, sesuai pola brief; ini review dalam workspace, bukan izin publish dari browser. `event` adalah key brief untuk editor acara; bila domain internal memilih `events`, buat satu pemetaan yang tervalidasi.

## Alur pengguna utama

1. Publik: beranda → katalog → detail/demo → registrasi dengan template terpilih → wizard undangan → ringkasan. Demo tidak memerlukan login. PUB-01 memuat CTA katalog dan contoh; navigasi ini tetap berfungsi pada mobile.
2. Customer: ringkasan akun → satu next action → section editor → preview → checklist → publikasi. CUS-05/06 belum punya screenshot; desain fallback mengikuti primitive/kontrak, dicatat sebagai tambahan implementasi, bukan layar Stitch yang ditemukan.
3. Pembayaran: checklist terblokir entitlement → pilih paket → checkout/order valid → attempt provider → status server → aktivasi entitlement → customer mengonfirmasi publish. Entitlement aktif tidak memaksa checkout ulang. Expired membuat attempt baru sesuai order, dengan histori lama tetap ada.
4. Tamu: daftar/impor → mapping/preview/result → salin/buka WhatsApp → cover/token sah → buka → acara/lokasi → RSVP → ringkasan customer. “WhatsApp dibuka” tidak berarti pesan terkirim. Respons RSVP berbeda dari jumlah orang pendamping.
5. Akun: Google/email → callback sah → dashboard; lupa sandi → respons generik → token reset tervalidasi → login. Konflik metode → reauth metode lama → linking secara sah; jangan mengungkap keberadaan akun sebelum konteks aman.
6. Dukungan: tiket baru → percakapan → status/notifikasi. Screenshot daftar tidak membuktikan chat, jadwal concierge, atau nomor kontak operasional tersedia.
7. SUPERADMIN: monitoring pembayaran → detail provider/attempt → rekonsiliasi webhook → retry terverifikasi/idempoten → audit. Tombol retry tidak memberi jalur “Set PAID” manual tanpa verifikasi.
