26. PRISMA + NEON RULES
============================================================

Use PostgreSQL on Neon.

Use Prisma ORM.

Before implementation:

1. inspect installed Prisma version
2. read the current Prisma documentation relevant to the installed version
3. do not mix Prisma v6 and Prisma v7 configuration styles
4. keep Prisma schema in prisma/schema.prisma
5. keep migrations under prisma/migrations
6. generate Prisma client according to current Prisma version
7. use a singleton Prisma client for server runtime
8. avoid creating a new PrismaClient per request

For Neon:

Use pooled runtime connection for application traffic.

Use direct connection for CLI/migrations where required by the chosen Prisma/Neon setup.

Recommended environment concept:

DATABASE_URL=pooled runtime URL
DIRECT_URL=direct migration URL

Do not commit secrets.

Create:

.env.example

with variable names only.

The agent must adapt exact Prisma/Neon configuration to the versions already installed.

29. MAYAR PAYMENT ARCHITECTURE
============================================================

Use Mayar as the external payment provider.

IMPORTANT:

The frontend must never be the source of truth for payment status.

The system must trust only verified server-side payment confirmation.

Recommended architecture:

Customer UI
    ↓
Create internal Order
    ↓
Server Payment Service
    ↓
Mayar API
    ↓
Payment / QRIS
